# Вход и выход

## Вход

На вход агент получает полный текст статьи в следующем формате:

```text
!! chapter: string
!! paragraph: 1
текст параграфа...

!! paragraph: 2
текст параграфа...

!! chapter: string
!! paragraph: 1
текст параграфа...
```

### Структура входных данных

* `chapter` — название главы статьи.
* `paragraph` — порядковый номер параграфа внутри соответствующей главы.
* После строки `!! paragraph: N` следует полный текст соответствующего параграфа.
* Нумерация параграфов начинается с `1` и ведётся отдельно для каждой главы.
* Статья может содержать любое количество глав и параграфов.

Дополнительно агенту предоставляются:

* `reference.md`;
* `instruction.md`.

## Выход

Результат должен быть только валидным JSON, без Markdown, комментариев, пояснений или любого другого текста вне JSON.
Корневой элемент результата — массив объектов.
Каждый объект описывает одно место в статье, содержащее одно или несколько нарушений.

Формат:
```json
[
  {
    "place": {
      "chapter": "string",
      "paragraph": 1
    },
    "quote": "string",
    "types": [
      {
        "number": 1,
        "name": "string"
      }
    ],
    "problem": "string",
    "corrections": [
      "string"
    ]
  }
]
```

### Поля объекта

#### `place`
Объект, указывающий местоположение найденного нарушения.
* `chapter` — точное название главы из входного текста.
* `paragraph` — номер параграфа из входного текста.
```json
"place": {
  "chapter": "Introduction",
  "paragraph": 3
}
```

#### `quote`
Точная цитата из исходного текста статьи.
Требования:
* цитата должна дословно совпадать с текстом статьи;
* нельзя исправлять, перефразировать или изменять цитату;
* цитата должна быть непрерывным фрагментом исходного текста;
* цитата должна содержать минимальный фрагмент, необходимый для идентификации нарушения.

#### `types`
Массив типов нарушений, относящихся к данной цитате.
Каждый элемент содержит:
* `number` — номер типа нарушения согласно `reference.md`;
* `name` — точное название типа нарушения согласно `reference.md`.
Если одна цитата содержит несколько типов нарушений, все они указываются в одном массиве `types`.

#### `problem`
Одно человеко-читаемое описание проблемы, обнаруженной в указанной цитате.
Если цитата содержит несколько типов нарушений, все претензии к ней объединяются в одно значение `problem`.

#### `corrections`
Массив возможных исправлений исходной цитаты.
* Каждая строка должна содержать отдельную формулировку, которой можно заменить `quote`.
* Варианты должны быть расположены от наиболее удачного к менее удачному.
* Допускается несколько вариантов исправления.
* Если подходящее исправление отсутствует, массив может быть пустым.
Все содержательные строковые значения (`quote`, `problem`, `corrections`) должны быть написаны на языке соответствующего фрагмента статьи.

### Правила группировки
Если одна и та же цитата содержит несколько нарушений, создаётся **один объект**, а все типы нарушений перечисляются в его поле `types`.
Если нарушения относятся к разным цитатам, для них создаются разные объекты.

### Отсутствие нарушений
Если в статье нет нарушений, результатом должен быть пустой массив:
```json
[]
```

### Ограничения формата
Каждый объект результата должен содержать только следующие поля:
* `place`;
* `quote`;
* `types`;
* `problem`;
* `corrections`.
Внутри `place` допускаются только:
* `chapter`;
* `paragraph`.
Внутри каждого элемента `types` допускаются только:
* `number`;
* `name`.
Не добавляй дополнительные поля.
Результат должен быть синтаксически валидным JSON.
