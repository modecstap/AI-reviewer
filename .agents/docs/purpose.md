создать сервер предоставляющий API для создания рецензии на статью содержащую претензии к её тексту разбитые по параграфам.
при получении файла программа запускает AI агенты которые проверяют статью на соответствие свойствам академичности и составляют файлы с отчётами по своей области. после того как все агенты вернут отчёты собирается отчёт по статье где на каждый параграф к главе собираются претензии по различным свойствам.

формат файловой структуры для каждой статьи:
- article.docx
- output_dir
    - 1
        - article.txt
        - caution.json
        - conciseness.json
        - consistency.json
        - correctness.json
        - impersonality.json
        - literacy.json
        - structure.json
        - report.json
        - report.html
        - report.css
        - report.pdf
    - 2
        - ...
    - ...

article.docx - исходный текст статьи. `ai_reviewer/splitter/` разбивает его на главы и параграфы.
- id главы - её заголовок, где пробельные символы схлопнуты в один пробел; повторы получают ` (2)`, ` (3)`… с учётом регистра; текст до первого заголовка идёт в главу `Без заголовка`. id главы - это `place.chapter` в `<property>.json` и `chapter` в report.json.
output_dir - папка с подпапками прогонов ревью. CLI `python -m ai_reviewer.main <article.docx> <output_dir>` делает полный прогон. каждый прогон (`AIPool.execute`, `ai_reviewer/ai_pool/`) создаёт подпапку {N} = максимальный существующий номер + 1 (первая - `1`). в ней `article.txt` - размеченный текст, отданный агентам, и `<property>.json` только успешных агентов, где `<property>` - id свойства = имя его папки в `properties/` (например `caution`). после сборки отчёта в ней же лежит `report.json`. .json файлы с найденными проблемами имеют общий формат:
[
    {
        place: {
            chapter: string,
            paragraph: num
        },
        quote: string,
        types: [
            {
                number: num,
                name: string
            },
            ...
        ],
        problem: string
    },
]

report.json - итоговый документ прогона в `<output_dir>/<N>/`. собирается `ai_reviewer/report/` из `article.txt` и файлов свойств этой папки в формате
[
    {
        "chapter": string,
        "claims": [
            {
                "paragraph": num,
                "<property>": [
                    {quote: string, types: [{number: num, name: string}, ...], problem: string},
                    ...
                ],
                ...
            },
            ...
        ]
    },
    ...
]
- претензия - все поля исходного элемента файла свойства, кроме `place`.
- ключ свойства, параграф и глава без претензий не пишутся; нет претензий - файл равен `[]`.
- главы идут в порядке `article.txt`, параграфы - по возрастанию, ключи свойств - по алфавиту, претензии свойства - в порядке его файла.
- одинаковые цитаты разных свойств не сливаются.
- претензии с неверным `place` (нет главы или параграфа в `article.txt`) и битые файлы свойств пропускаются с warning.
- UTF-8, кириллица хранится как есть.

report.html, report.css, report.pdf - печатная версия report.json. пишет `RunDirWriter` (`ai_reviewer/run_dir/`) через `ai_reviewer/report/printer/`. report.html - HTML-фрагмент, report.css - его стили (шрифты указаны как `fonts/…` относительно CSS), report.pdf - PDF, собранный WeasyPrint из этих HTML и CSS плюс разрывы страниц перед параграфами, вычисленные при сборке PDF (в report.css их нет). титульная страница: VSRT, AI-Reviewer, дата создания. следующая страница - статистика: заголовок «Статистика», число претензий всего, сводная таблица свойство × номер типа и под ней мелким шрифтом легенда названий типов; всё на одном листе. строки - все свойства каталога `properties/` и report.json, столбцы - все номера типов каталога (`### N.` в разделе `## Violation types` файла `reference.md`) и report.json, плюс столбец «Всего» (число претензий свойства). ячейка - число претензий свойства с этим номером типа (претензия с несколькими типами считается в каждом); тип без номера идёт только в итоги. 0 печатается бледным, ячейка несуществующего у свойства типа пустая серая. дальше каждая глава с новой страницы: слева текст параграфа, где цитаты его претензий выделены заливкой, справа его претензии. параграф, чья подпись и текст не влезают в остаток страницы, начинается с новой страницы; претензии не учитываются, первый параграф главы остаётся под заголовком, текст длиннее страницы разрывается. имена свойств и типов печатаются на языке печати (`ReportLabels`): русские берутся из `properties/translation/ru.json` по id свойства и номеру типа, без перевода печатается исходное имя из report.json.
